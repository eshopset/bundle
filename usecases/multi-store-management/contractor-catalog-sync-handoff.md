**contractor Shopify Data Sync handoff** means each Shopify store keeps its own plan, app enables, and usage limits—not a shared multi-store control center. This use case shows how in-house teams, agencies, and freelancers run contractor Data Sync setup and Logs handoff store by store with EShopSet.

_Contractors: configure Data Sync (Google Sheets → Shopify) on a client store, prove preview/apply in Logs, then hand off Settings ownership—one plan per store._

## Outcomes

- Scoped to one Shopify store and its plan row limits
- Preview → apply → Logs as the acceptance checklist
- Handoff packet: sheet link, mapping, schedule, owners

## Why handoffs fail without Logs

Merchants inherit broken schedules when contractors leave without proof. A Logs-backed handoff shows the last successful run and who owns the sheet.

## How it works in EShopSet

Enable Data Sync, map columns, match keys, run manual preview/apply, confirm Logs, optionally set schedule, then write a one-page handoff. Billing remains on the store’s [plan](https://eshopset.com/pricing/).

## Example: two-week catalog cleanup

A contractor imported 2,400 SKUs on Growth, fixed 37 barcode errors after preview, applied clean, scheduled daily, and left a Loom + sheet with match-key rules. Agency ops owned Logs thereafter.

## Playbook

1. Confirm store plan and row needs.
2. Connect sheet; map; match keys; policies.
3. Preview; fix; apply; save Logs evidence.
4. Document schedule and sheet owners.
5. Revoke contractor access after acceptance.

## What to measure

- Preview error count at handoff = 0 critical
- Handoff doc completed before access revoke
- First post-handoff scheduled run success

## Proof points

- **Preview** — Acceptance gate
- **Logs** — Proof of clean run
- **1 store** — Scope of engagement
